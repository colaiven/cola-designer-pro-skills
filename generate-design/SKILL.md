# 生成大屏 / 报表设计文件（.cd）

本 Skill 分析用户需求，结合 Cola Designer Pro 支持的组件与配置项，直接产出一份可导入系统的大屏/报表 `.cd` 设计文件。**官方网站：https://cdesign.fun/**（可在线体验设计器与模板）。支持两种模式：
- **单页大屏**（`scaleType: 1`）：固定画布大小（默认 1920×1080），全屏铺满展示
- **报告/长页**（`scaleType: 2`）：固定宽度 1920，高度按内容自动计算，竖向滚动浏览

> 组件与配置项清单见同目录 `references/component-catalog.md`。生成前先查阅该目录，确认要用的 cptKey 与 dataText 结构。

---

## 0. 软件版本号声明（重要）

- 当前支持的软件版本：**`2.7.18`**。
- `.cd` 文件内必须写入 `"version"` 字段；生成时默认填 `"2.7.18"`。
- **导入版本校验规则**（设计器导入逻辑）：取文件 `version` 的「主.次」版本号（如 `"2.7.18"` → `"2.7"`），要求它等于目标系统当前版本的「主.次」前缀（`env.version.startsWith(upVersion)`）。即文件版本与目标系统必须**同主.次版本**。
- 因此：若告知用户的系统是其它版本，须先问清版本号，将文件的 `version` 填成与该系统**主.次一致**的值（例如目标为 2.6.x 填 `"2.6.0"`，目标为 2.7.x 填 `"2.7.x"`）。默认按 `2.7.18` 输出。
- `designType` 字段**固定为 `"screen"`**（大屏）。不要写其它值。

## 1. `.cd` 文件结构

`.cd` 本质是一个 UTF-8 **JSON 文本文件**。顶层结构如下：

```json
{
  "version": "2.7.18",
  "designType": "screen",
  "title": "示例大屏",
  "simpleDesc": "",
  "scaleX": 1920,
  "scaleY": 1080,
  "scaleType": 1,
  "bgColor": "#0a1a2f",
  "bgImg": "",
  "viewCode": "",
  "waterMark": { "enabled": false, "text": "cola-designer", "fontColor": "#fff", "fontSize": 14, "alpha": 0.6 },
  "components": [ /* 组件实例数组，见下 */ ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|------|------|------|
| version | ✅ | 软件版本号，见第 0 节 |
| designType | ✅ | **固定 `"screen"`**（大屏） |
| scaleX / scaleY | ✅ | 画布分辨率（px）。单页默认 1920×1080；报告类 scaleY 按 4.1.2 节公式计算 |
| scaleType | 建议 | `1`=全屏铺满（单页大屏）；`2`=按比例缩放，竖向滚动（报告/长页）。详见 4.1.1 与 4.1.2 |
| bgColor | ✅ | 大屏背景色（hex） |
| bgImg | 置空 | 背景图，**固定 `""`**。背景图须在设计器**在线图片素材库**选择，生成时不填，导入后由用户自行配置 |
| title / simpleDesc / viewCode | 可选 | 标题、描述、访问码 |
| waterMark | 可选 | 水印配置，字段见下方「waterMark 结构」 |
| socketUrl | 可选 | websocket 推送地址，默认无（省略） |
| components | ✅ | 组件实例数组 |

**waterMark 结构**（可选，默认不启用水印）：
```json
{ "enabled": false, "text": "cola-designer", "fontColor": "#fff", "fontSize": 14, "alpha": 0.6 }
```
| 字段 | 说明 | 取值 |
|------|------|------|
| enabled | 是否启用水印 | `true` / `false`，默认 `false` |
| text | 水印文本 | 字符串 |
| fontColor | 水印文字颜色 | hex（如 `#fff`） |
| fontSize | 字体大小 | 12–150（px） |
| alpha | 透明度 | 0–1（步进 0.1） |

> 内存上 `enabled=true` 时，整个 waterMark 对象会作为 `t-watermark` 的 `watermark-content` 传入，其中 `text`/`fontColor`/`fontSize` 即水印内容与样式。生成默认关闭水印即可，需要时按上述字段配置。

### 组件实例结构（components 数组内每一项）

```json
{
  "id": "e8f6b2c1-4a3d-4f9e-9c8a-1234567890ab",
  "cptKey": "cpt-text",
  "cptOptionKey": "cpt-text-option",
  "cptTitle": "标题",
  "cptX": 100,
  "cptY": 80,
  "cptWidth": 600,
  "cptHeight": 60,
  "rotate": 0,
  "cptShow": true,
  "cptOption": {
    "attribute": { "textColor": "#ffffff", "textSize": 32, "fontWeight": "bold", "textAlign": "center", "enableGradual": 1 },
    "cptDataForm": { "dataText": "{\"value\":\"某市智慧城市运营中心\"}", "dataSource": 1, "pollTime": 0 },
    "interaction": { "active": false, "intType": "display", "objMap": { "default": { "show": [], "hidden": [], "changeovers": [], "drillDesignId": "", "designType": "screen", "redirectUrl": "", "redirectType": "_blank" } }, "changeDataset": [], "paramType": "auto", "paramName": "", "paramValue": "" }
  }
}
```

字段说明：

| 字段 | 必填 | 说明 |
|------|------|------|
| id | ✅ | 组件唯一标识；生成一个 uuid 风格的唯一字符串（任意唯一串即可，作为图层 key） |
| cptKey | ✅ | 组件唯一标识，须是目录中已存在的组件（见 catalog） |
| cptOptionKey | ✅ | 属性表单标识，默认 = `cptKey + '-option'`；共用表单的组件要用目录里标注的 cptOptionKey |
| cptTitle | 建议 | 图层名（图层列表显示），可填中文名 |
| cptX / cptY | ✅ | 相对画布左上角坐标（px） |
| cptWidth / cptHeight | ✅ | 组件尺寸（px） |
| rotate | 可选 | 旋转角度（度），默认 0 |
| cptShow | ✅ | 是否显示，默认 true |
| cptOption | ✅ | `{ attribute, cptDataForm?, interaction }`；`interaction` **每个组件都必须带**（见下） |

**z 层级**：`components` 数组下标即图层顺序，**下标 0 在最顶层**（最后一项在底层）。全屏装饰/背景可放数组末尾，需要叠在其它组件之上的放前面。

**配置项枚举约束**：不少属性是下拉/单选，只能取固定值（如文本 `textAlign` 仅 `left/center/right`；echarts 位置字段既支持 `left/center/right/top/middle/bottom` 关键字，也支持 `"20"`/`"20px"`/`"20%"` 数值）。生成时以 `references/component-catalog.md` 的「通用取值枚举」为准，**禁止臆造不存在的选项值**。

**interaction（每个组件都必带，且必须是完整对象）**：`.cd` 导入是原样载入 `components`，不会像"拖拽新组件"那样补默认 interaction。设计器右栏在选择组件时（`config-bar.vue` 的 `showCptConfig`）会**无条件**读取 `interaction.objMap.default` 与 `interaction.multi`，交互面板另读 `active / intType / changeDataset / paramType / paramName / paramValue`。因此：

- **任何组件**的 `interaction` 都必须是下方「完整默认交互对象」的结构——缺整个 `interaction` 或缺 `objMap`，点选组件即报错。
- 可点击交互的组件（文本、按钮、图表等大多数）→ 直接用完整默认对象（`intType:"display"`），如上方示例。
- 纯展示/不支持交互的组件 → **同样携带完整默认对象，仅把 `intType` 改为 `"none"`**（目录里标注 `intType: none` 的组件，如轮播图/视频/静态表格/滚动表格/滚动列表/数字翻牌器/增长指标/动态环形图/水球图/HTML 查看器等）。HTML 查看器（cpt-html-viewer）支持两种模式：iframe 嵌入 HTML 代码、富文本渲染（`codeType='richText'` 时直接渲染 HTML 内容）。**不要只写 `{ "intType": "none" }`**，否则缺 `objMap`，导入后点选会报错。
- 选项卡/导航器/跳转等**多选项**交互组件 → 在完整默认对象上附加 `"multi": true`（`multi` 非必需，可省略）。

完整默认交互对象（与 `default-action-obj.js` 一致）：
```json
{
  "active": false,
  "intType": "display",
  "objMap": { "default": { "show": [], "hidden": [], "changeovers": [], "drillDesignId": "", "designType": "screen", "redirectUrl": "", "redirectType": "_blank" } },
  "changeDataset": [],
  "paramType": "auto",
  "paramName": "",
  "paramValue": ""
}
```

**cptTitle**：填组件中文名（如「文本」「边框」「基础折线图」）即可，作为图层列表名。

## 2. 执行流程（务必先确认再生成）

1. **明确需求**：大屏主题/行业（如智慧城市、园区能耗、电商销售、机房监控、金融风控……）、要展示哪些指标与图表、整体色调。
2. **选择布局模板与风格**：单页大屏根据场景从 4.1.1 节的模板库中选择（A–H），用户未指定风格时参考 4.2 节按行业缩小候选后**随机选择**，同一会话连续生成时须更换模板与配色。报告/长页类需求按 4.1.2 节计算高度，并**必须从 4.1.3 节报告风格库中随机选择**风格主题、章节序号形式与章节编排组合，禁止每次产出同质化报表。
3. **确认分辨率**：默认 `1920×1080`，询问用户是否需要其它分辨率（如 2K/4K 或非 16:9）。
4. **确认缩放模式**（`scaleType`）：
   - `1` 全屏铺满 —— 单页大屏默认使用，画面随浏览器窗口拉伸铺满、无滚动条。
   - `2` 按比例缩放 —— 报告/长页类使用，等比缩放，超出高度产生**竖向滚动条**；此时 `scaleY` 按 4.1.2 节公式计算（≥ 所有组件 bottom + M）。
   - 单页大屏 → 推荐 1；报告类 → 推荐 2。
5. **确认数据来源**：本 Skill 只生成**静态数据源**（`dataSource: 1`）文件。数据内容可**随机合理生成**，或**实时拉取互联网真实数据**（用搜索/联网工具获取真实数值，如 GDP、人口、排行、天气等）。询问用户偏好"随机贴近真实"还是"联网真实数据"。
6. **产出设计框架并请用户确认**（务必执行，确认前不落盘）：用**简短文字描述**把框架呈现给用户，**无需列出具体组件清单/坐标/`cptKey`**，等待用户确认/修改，确认后才进入下一步（产出文件）。
   - **布局概览**：几句文字说明画布分区与组件摆放（如"顶部标题 + 4 个 KPI 横排 + 中部 3×2 图表网格 + 底部地图/表格"）；报告类需一并说明所选**风格主题与章节序号形式**（见 4.1.3 节），供用户确认或更换。
   - **统计指标建议**：基于所选行业/场景，主动判断并**询问用户是否需要增加统计指标**，同时给出具体建议（如：可补充哪些 KPI 卡、排行榜、趋势图、占比图；哪些指标适合用翻牌器/仪表盘/词云呈现），供用户取舍。
   - 用 `AskUserQuestion`（或直接提问）请用户确认框架，选项可含「按此框架生成 / 调整布局 / 增删指标 / 更换模板」。用户确认（或给出修改意见并二次确认）后才落盘写入 `.cd` 文件。
7. **产出文件**：结合 `references/component-catalog.md` **完善细节** —— 以上一步确认的**框架（布局结构、组件类型、所选统计指标）**为基准，对照 catalog 选定每个组件的 `cptKey`/`cptOptionKey`、计算坐标/尺寸、填充指标数据，组装完整 JSON，写成一个 `<标题>.cd` 文件。

> ⚠️ 分辨率、缩放模式、布局模板、**设计框架**未经用户确认前，不落盘生成文件。

## 3. 数据生成规则

- 所有组件 `cptDataForm` 一律：
  - `dataSource: 1`（静态）
  - `pollTime: 0`（不轮询）
  - `dataText`: **JSON 格式的字符串**（注意内外引号转义）
- `dataText` 的 JSON 结构必须与所选组件一致（见 catalog 每项标注的 dataText 示例/结构）。
- 数据值策略：
  - **随机生成**：数值在合理区间内、且符合组件语义（百分比 0–100、金额量级合理、时间序列有波动、排名有梯度）。相同业务指标在不同组件间保持一致量级，避免自相矛盾。
  - **联网真实数据**：搜索/抓取真实数据（如各省 GDP、城市人口、股票指数、天气），按组件 dataText 结构重组。
- 文案、标题、单位等用中文；图表标题两要素：主语 + 指标（如「各区域用电量分布」）。
- 地图类组件：`provinceCode/cityCode` 可指定省市（6 位 adcode），`china` 全国地图前端内置、省市地图 geojson 由后端 `design_geo_data` 内置提供；`dataText` 的 `name` 须与对应地图区域名一致（详见 catalog 地图小节）。

## 4. 布局建议（1920×1080 参考）

### 4.1 坐标与宽高的确定性计算（生成时必须按此计算，不要凭感觉摆位）

组件 `cptX/cptY/cptWidth/cptHeight` 必须按下面的公式算出，保证不重叠、不越界：

**基准常量**：页边距 `M = 24`，组件间距 `G = 16`；画布 `W = scaleX`，`H = scaleY`；内容区宽 `CW = W - 2*M`。`cptX/cptY` 是左上角坐标（px），原点在画布左上角。

**等宽分栏**（一行 N 个等宽块）：
- 每块宽 `colW = (CW - (N-1)*G) / N`
- 第 i 块（i 从 0 起）`x = M + i * (colW + G)`

**纵向堆叠**：从上到下按「区段」排，每段行高按组件类型定（标题 60–70 / KPI 120–150 / 图表格 280–400 / 底部地图·表格 300–420）。段间留 `G`：
- 段顶 `yTop = 上一段 bottom + G`；首段 `yTop = M`（段 bottom = yTop + 段高）

### 4.1.1 单页大屏布局模板库（scaleType 1，1920×1080）

**⚠️ 风格多样性要求**：根据用户需求的行业/场景/数据特点，从下列模板中选择最合适的一种。如用户未指定风格，**随机选择**一种（难以抉择时可用当前时间的分钟数个位数对候选数取模来决定）；同一会话连续生成多张时，必须使用与上次**不同的模板和配色**，禁止次次都是「模板 A + 深色科技蓝」。

### 4.1.2 报告/长页布局与高度计算（scaleType 2）

报告类长页使用 `scaleType: 2`（按比例缩放，竖向滚动）。报告结论/描述/说明等长文本优先使用cpt-html-viewer组件的富文本模式（`codeType='richText'`），支持加粗、高亮、列表、图片等富文本格式，无需iframe嵌入。**核心原则：`scaleY` 必须按所有组件实际堆叠总高度计算，绝不能让图表被压缩变形。** 报告的**风格主题、章节序号形式、章节编排**必须按 4.1.3 节风格库随机选择，避免所有报表千篇一律。

**组件最低高度约束**（防压缩）：
- 标题文本：≥ 56px
- 章节标题：≥ 48px
- KPI 指标卡：≥ 120px
- 图表/表格/地图：≥ 300px（推荐 340–400px）
- 时间轴：≥ 200px
- 滚动列表：≥ 250px
- 装饰/边框：跟随被框组件

**高度计算公式**：
```
当前区段 top = 上一区段 bottom + G（首段 top = M）
区段 bottom = top + 该区段内最高组件的 height
scaleY = 最后一个组件的 bottom + M
```

**报告典型章节结构**（纵向堆叠；各章组成可以不同，见 4.1.3 节编排库）：
| 元素 | 高度 | 说明 |
|------|------|------|
| 章节标题 `cpt-text`（或带文字装饰条/边框标题） | 56px | 序号与标题形式见 4.1.3 节 N 库 |
| 章节装饰 `cpt-dataV-decoration` | 40px | 标题下方横线装饰（可选） |
| KPI 行（N 列） | 130px | 可选 |
| 图表行（M 列） | 340px | 每行可放 1–3 个图表 |
| 补充说明/表格 | 280px | 可选 |
| 章间留白 | G=16px | |

**工作示例**（1920×2800 报告，3 个章节）。⚠️ 本示例**仅演示高度堆叠算法**：其中的序号写法、标题样式与「KPI 行 + 图表行」的章节编排只是众多可能中的一种，实际生成时务必按 4.1.3 节随机选择，**不要照抄**：
```
M=24, G=16, CW=1872

[总标题] y=24, h=72, bottom=96
[装饰线] y=112, h=30, bottom=142

── 章节 01（序号形式仅为演示，实际按 4.1.3 节 N 库选择）──
[章标题] y=158, h=56, bottom=214
[KPI×3]  y=230, h=130, bottom=360  (colW=613, x=24/653/1282)
[图表×2] y=376, h=340, bottom=716  (colW=928, x=24/968)

── 章节 02 ──
[章标题] y=732, h=56, bottom=788
[图表×3] y=804, h=340, bottom=1144 (colW=613, x=24/653/1282)
[表格]   y=1160, h=280, bottom=1440

── 章节 03 ──
[章标题] y=1456, h=56, bottom=1512
[地图]   y=1528, h=500, bottom=2028
[KPI×4]  y=2044, h=130, bottom=2174
[图表×2] y=2190, h=340, bottom=2530

scaleY = 2530 + 24 = 2554 → 取整 2600
最终 scaleY = 2600（≥ 所有组件 bottom + M）
```

**关键校验**：
- `scaleY` 必须 ≥ 最大组件 bottom + M，宁大勿小（多余空白可在设计器裁切）
- 每个图表组件高度 ≥ 300px，若空间不足则增加 `scaleY` 而非压缩图表
- 若按 1920 宽度计算，单行只放 1 个图表时宽度可达 1872px，放 2 个各 928px，放 3 个各 613px
- 报告中 `cpt-dataV-border` 可用于框住整个章节区域（尺寸 = 章节内容区 + 内边距），增强分节感

**布局校验（生成后必查）**：
- 单页（scaleType 1）：每个组件满足 `0 ≤ cptX`、`cptX+cptWidth ≤ W`、`0 ≤ cptY`、`cptY+cptHeight ≤ H`。
- 报告（scaleType 2）：横向同上；纵向满足 `cptY+cptHeight ≤ scaleY`（scaleY 按 4.1.2 公式计算得出，非固定值）。
- 有意叠加的除外：边框/装饰只用于局部框住图表或指标卡，**不要铺满全屏**；标题可叠在局部边框内。只有背景图才需铺满 `[0, 0, W, H]`。
- 若某段算出的高度过小（<80px），优先裁掉次要段或降低该段高度，而不是让它越界。
- 报告类额外校验：每个图表组件高度 ≥ 300px，若不足则增大 `scaleY` 而非压缩图表。

## 5. 输出与导入

1. 组装好完整 JSON 后，写入文件 `<标题>.cd`（纯 UTF-8 JSON，无需 BOM）。
2. 告知用户导入方式：进入设计器 → 顶部/操作栏「导入」选择该 `.cd` 文件；导入成功后 `components`、`scaleX/scaleY`、`bgColor/bgImg` 会被应用到当前画布，之后可正常保存/预览/分享。
3. 说明产物清单：用了哪些组件、各自分组、数据是随机还是联网真实、分辨率与缩放模式建议；并**提醒用户背景图 `bgImg` 已置空**，可在设计器「大屏配置 → 背景图片」从在线素材库自行选择。

## 6. 注意事项与已知限制

1. **版本不匹配会拒绝导入**：报"跨度过大"时，把 `version` 改成目标系统的同主.次版本号。
2. **颜色尽量用静态 hex/rgba**：catalog 已把 `defaultColor` 展开为具体色值，不要写 `defaultColor[i]` 这类占位。
3. **dataText 是字符串**：写 JSON 时务必 `dataText` 为字符串（内容为 JSON）而非对象/数组。
4. **cptKey 必须存在**：设计系统中不存在的 cptKey 会导致该组件报"组件未实现"或渲染空白，务必以 catalog 为准。
5. **报表类≠仪表盘**：本 Skill 产出 `designType: 'screen'` 的大屏设计文件，支持单页（scaleType 1）和报告长页（scaleType 2）两种模式；仪表盘（report）走另一套 report-editor 设计器，不在本技能范围。
6. **报告 scaleY 计算**：报告类长页的 `scaleY` 必须按 4.1.2 节公式从组件实际堆叠高度算出，不能写死 1080，否则图表会被压缩变形。
7. **大文件产出策略（首选生成器脚本，备选分片拼接）**：报告长页 `.cd` 动辄几十 KB（约 60 个组件即 ~84KB），一次性 Write 会因工具参数超长被截断而报 `Error writing file`（input could not be parsed as JSON）；用 Bash heredoc 一次写大文本同样易失败。
   - **首选：生成器脚本**（输出量可省 60% 以上，已验证可行）。写一个 Node 脚本产出 `.cd`，脚本内把高度重复的结构只定义一次，正文只写"差异"：
     - `INT(intType, multi)` 工厂生成每个组件必带的完整 interaction 对象（完整对象每组件重复一遍，约占文件 20%）；
     - 每类组件一个工厂函数（如 `text()/quota()/line()/column()/pie()/html()/map()/table()`），内置该组件完整 attribute 模板，用 `Object.assign` 支持局部属性覆盖，入参只收坐标、标题文案、dataText 等差异项；
     - 数据与布局分离：指标数据（月度值、分省值、KPI 等）用数组集中管理再映射到组件，便于自洽检查；
     - 末尾 `JSON.stringify(design, null, 2)` 落盘，再回读做下一条校验。
   - **备选：分片拼接**。不用脚本时，按章节把 JSON 切成多个片段（**单片 ≤ 15KB**），片段边界停在组件对象结尾（`},` 处），最后一片以 `}` + `]` + `}` 收尾；逐片用 Write 写入临时目录（如 `.cd-parts/part1 … partN`），再 `cat part1 … partN > "标题.cd"` 拼接。
8. **产出后必须脚本校验**（无论用哪种产出方式）：用 node 校验——整体 `JSON.parse` 通过、每个组件 `dataText` 可解析且 `dataSource===1`、`cptKey` 在目录中存在且 `cptOptionKey` 匹配、坐标不越界、组件间无意外重叠、`interaction` 为完整对象、图表高度 ≥300px、数据总量自洽（如月度合计等于年度总量）。校验通过后清理临时片段目录；生成器脚本可按需保留，便于后续微调重新生成。
